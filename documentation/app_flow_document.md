# AI Schedule Auditor App Flow Document

## Onboarding and Sign-In/Sign-Up
When a brand-new user visits the application, they arrive at the landing page. This page welcomes them with a brief introduction to the AI Schedule Auditor and presents options to sign in or sign up. To create a new account, the user clicks the "Sign Up" link. They are then taken to a simple registration form where they enter their email address, choose a secure password, and confirm their password. After submitting, they receive a confirmation message indicating that their account has been created. Returning users select "Sign In" from the landing page and enter their credentials on the login form. If a user forgets their password, they click the "Forgot Password" link, submit their email address, and receive a reset link. Following the link allows them to choose a new password, after which they can sign in normally. Once authenticated, the session persists until the user clicks the "Sign Out" button, which appears in the application header or user menu, ending the session immediately.

## Main Dashboard or Home Page
After signing in, the user is redirected to the dashboard, which serves as the central hub of the application. At the top, a header bar displays the application name and a user menu with options for account settings and signing out. Below the header, the left side may show a navigation panel or simply the dashboard content area if a sidebar is not used. The main section presents three key components: a calendar view that visually lays out all scheduled events, a metrics chart that highlights time allocation patterns, and summary cards that display high-level insights such as total meetings or hours scheduled this week. Within this same view, the chat assistant component sits at the bottom or side, ready to accept natural language schedule inputs. From this dashboard, users can move freely to other flows, such as opening account settings or engaging with the chat interface.

## Detailed Feature Flows and Page Transitions
When a user wants to add or audit an event, they focus on the chat assistant within the dashboard. They type a message like "Schedule a project kickoff on Thursday at 2 PM for two hours," and hit send. The chat component sends this message to the backend chat API route. On the server, the API authenticates the user, forwards the text to the AI model via the Vercel AI SDK, and uses function calling to extract structured event details. Once the AI returns the event parameters, the server saves the new event record and the chat message in the database. The response then flows back to the chat interface where the assistant confirms the event creation. The dashboard calendar view automatically refreshes, showing the new event in place. Users can repeat this process for any scheduling need, refining or canceling events through follow-up messages like "Move that meeting to 3 PM" or "Delete the Thursday event." Each adjustment triggers the same API route, updating the database and reflecting changes in the calendar.

## Settings and Account Management
Users manage their personal information by clicking on their name or avatar in the header, which opens an account settings page. Here they can update their email address, change their password, and configure preferences such as notification settings. Although there is no billing or subscription flow in the current version, this section could expand to include subscription details later. After saving any changes, the user sees a confirmation banner and can navigate back to the home dashboard via a link in the page header or by selecting the dashboard option in the navigation panel. Signing out from the account settings page also returns them to the landing page and ends the session.

## Error States and Alternate Paths
If a user enters incorrect credentials on sign-in, the login form displays an error message stating that the email or password is invalid. During password recovery, an expired or invalid reset token generates an error screen prompting the user to request a new reset link. In the chat flow, if a message fails to reach the server due to network issues, the chat component shows a retry button alongside an error notice. If the AI API call returns an unexpected error or the function calling fails, the assistant replies with a friendly message indicating that it could not process the request and suggests trying again. On any page, if the session times out or the user attempts a restricted action, the app redirects them back to the sign-in page with a note that they need to reauthenticate.

## Conclusion and Overall App Journey
From landing on the homepage to signing up and verifying their email, users quickly reach the dashboard where they can interact with a chat assistant to build and adjust their schedule in plain English. Each chat message is transformed into calendar events by the AI, and the dashboard updates in real time to visualize these items. Users can manage their account details, recover forgotten passwords, and sign out whenever they wish. Throughout the experience, error messages guide them past invalid inputs and connectivity hiccups, while the simple interface keeps the focus on effortless schedule auditing and optimization. The natural end goal for any user is a clear, visual calendar filled with accurately parsed events and insightful metrics that help them understand and improve their time use.
